# 월 10만원 적립 자동매매 — 무엇이 가능하고 무엇이 불가능한가

> 목표: 매월 10만원씩 넣고, 그 돈만으로 자동매매. 한 방을 노리지 않고
> **자주 조금씩** 차익을 쌓는다.
>
> 결론부터: **"소액 · 저위험 · 꾸준히"는 옳은 방향이다. 그러나 "자주 많이 거래"는
> 그 목표를 이루는 수단이 아니라 방해물이다.** 이유를 숫자로 보인다.

모든 수치는 `scripts/small_account_sim.py` 로 재현 가능하다.

```bash
python scripts/small_account_sim.py
```

## 1. 거래 횟수는 수익원이 아니라 비용 증폭기다

한 번 사고파는 데 드는 비용(왕복)은 확정적으로 나간다.

| 대상 | 왕복 비용 | 10만원 거래 시 |
|---|---|---|
| 국내주식 | 0.310% | 310원 |
| 코인 (업비트) | 0.200% | 200원 |
| 코인 (바이낸스) | 0.260% | 260원 |
| 미국주식 | 0.080% | 80원 |

거래 1회의 기대손익은 이렇게 쓸 수 있다.

```
1회 기대손익 = (평균 차익) − (왕복 비용)
N회 총손익  = N × [ (평균 차익) − (왕복 비용) ]
```

여기서 **N을 키우는 것은 괄호 안의 부호를 바꾸지 못한다.** 괄호가 양수면 N을 키워
이득이 커지고, 음수면 N을 키워 손실이 커질 뿐이다. 그리고 아무 엣지가 없는
상태에서 괄호는 정확히 **−(왕복 비용)** 이다.

거래 빈도별로 "본전만 하려면 총수익률이 얼마나 나와야 하는지"를 보면 체감된다.

| 빈도 | 연 거래수 | 국내주식 | 코인 |
|---|---|---|---|
| 월 1회 | 12 | 3.7% | 2.4% |
| 주 1회 | 52 | 16.1% | 10.4% |
| 주 2회 | 104 | 32.2% | 20.8% |
| 일 1회 | 250 | 77.4% | 50.0% |
| 일 5회 | 1,250 | 387.1% | 249.8% |

**"자주 많이 거래"의 상한은 여기서 정해진다.** 하루 한 번만 거래해도 코인에서
연 50%를 벌어야 본전이다. 실현 가능한 목표가 아니다.

### 실측: 같은 프레임워크로 확인

거래 빈도만 다른 전략들을 동일 조건에서 돌린 결과 (합성 시세, 7년).

| 전략 | 연 거래수 | 총수익(비용0) | 순수익(코인) | 순수익(주식) |
|---|---|---|---|---|
| 장기추세 (momentum 200) | 18 | 4.3% | 3.5% | 3.1% |
| 중기추세 (sma 30/120) | 6 | 6.4% | 6.2% | 6.1% |
| 단기추세 (sma 5/40) | 24 | 3.2% | 2.3% | 1.7% |
| 평균회귀 (zscore 20) | 21 | 0.6% | −0.2% | −0.7% |
| **초단기회귀 (zscore 5)** | **91** | **5.0%** | **1.3%** | **−0.7%** |

마지막 행이 핵심이다. 비용 전 연 5.0%를 내던 전략이 코인에서 1.3%, 주식에서
−0.7%가 된다. **전략이 나빠서가 아니라 거래를 많이 해서** 그렇게 된다.

## 2. 소액이면 코인이 구조적으로 유리하다 (더 오를 것 같아서가 아니다)

| | 국내주식 | 코인 (업비트) |
|---|---|---|
| 최소 거래 단위 | **1주** | **5,000원** |
| 10만원으로 분산 | 삼성전자 1주가 한계 | 20종목분 가능 |
| 왕복 비용 | 0.310% | 0.200% |
| 증권거래세 | 0.18% (매도) | 없음 |
| 거래 시간 | 평일 6.5시간 | 24시간 365일 |

10만원으로 국내주식을 하면 **삼성전자 1주(약 7만원)** 를 사면 끝이다. 분산도
리밸런싱도 불가능하다. 코인은 소수점 매매가 되므로 10만원으로도 5종목에
2만원씩 넣을 수 있다.

> **단, 코인은 변동성이 주식의 2~3배다.** 아래 시뮬레이션의 MDD −70%는 과장이
> 아니라 코인에서 실제로 일어나는 수치다. "적게 벌어도 좋으니 안전하게"가
> 목표라면 이 변동성부터 감당 가능한지 판단해야 한다.

## 3. 월 10만원 적립 7년 시뮬레이션

합성 시세(연변동성 70%, 코인 수준) 5종목 · 매월 10만원 적립 · 업비트 비용.

| 전략 | 연 거래수 | 투입원금 | 최종잔고 | 손익 | MDD |
|---|---|---|---|---|---|
| **적립식 매수 (거래 안 함)** | 1 | 820만 | 879만 | **+59만** | −75.6% |
| 그리드 4분할 (band 20%) | 206 | 820만 | 659만 | −161만 | −70.4% |
| 그리드 8분할 (band 10%) | 266 | 820만 | 662만 | −158만 | −70.4% |
| **추세추종 (sma 20/60)** | 13 | 820만 | 1,136만 | **+316만** | −34.6% |
| 고빈도 회귀 (zscore 5일) | 93 | 820만 | 643만 | −177만 | −58.9% |

> ⚠️ 합성 데이터이므로 **절대 수익률에는 아무 의미가 없다.** 실제 코인 시장의
> 미래 수익률을 예측한 것이 아니다. 의미 있는 것은 **거래 빈도와 손익의 관계**,
> 그리고 **비용 0 대비 비용 후의 낙폭**이다. 이 관계는 실데이터에서도 그대로 나타난다.

거래를 가장 적게 한 두 전략이 1·2위다. 이것이 우연이 아님은 다음 표가 보여준다.

### 거래 빈도의 대가 — 같은 그리드, 분할 단계만 다르게

| 설정 | 한 칸 | 연 거래수 | 비용0 수익 | 비용후 수익 | 비용이 먹은 몫 |
|---|---|---|---|---|---|
| band 30% / 2분할 | 15.0% | 89 | −8.1% | −9.8% | **−1.7%p** |
| band 20% / 4분할 | 5.0% | 206 | −7.8% | −10.0% | **−2.1%p** |
| band 10% / 8분할 | 1.2% | 266 | −6.6% | −9.3% | **−2.6%p** |
| band 5% / 10분할 | 0.5% | 206 | −5.8% | −8.5% | **−2.7%p** |
| band 2% / 10분할 | 0.2% | 135 | −6.0% | −8.8% | **−2.8%p** |

분할을 잘게 쪼갤수록 비용이 먹는 몫이 단조 증가한다. 맨 아래 행의 "한 칸 0.2%"는
**왕복 비용과 정확히 같다** — 한 칸을 움직여 봐야 전부 수수료로 나간다는 뜻이다.

**그리드 설계 규칙: 한 칸(`band / levels`)이 왕복 비용의 최소 10배는 되어야 한다.**
코인이면 한 칸 2% 이상. `GridTrading.step_pct` 로 확인할 수 있다.

```python
create_strategy("grid", {"band": 0.20, "levels": 4}).step_pct   # 0.05 = 5% (비용의 25배) OK
create_strategy("grid", {"band": 0.02, "levels": 10}).step_pct  # 0.002 = 0.2% (비용과 동일) 실패
```

## 4. 그러면 무엇을 해야 하나

### 목표 재설정 제안

| 버린 것 | 대체 |
|---|---|
| ~~자주 많이 거래~~ | **월 2~4회 이하.** 비용이 수익을 못 먹는 수준 |
| ~~차익을 조금씩 자주~~ | **적립 자체가 수익원.** 매월 10만원이 원금을 키운다 |
| ~~단기 차익 누적~~ | **하락 시 더 사는 구조.** 적립식의 본질 |

"한 방을 노리지 않는다"는 방향은 유지된다. 바뀌는 것은 **그것을 거래 횟수로
달성하려 하지 않는다**는 점이다.

### 현실적인 기대치

월 10만원 적립 · 12개월 후:

| 연 수익률 | 12개월 후 잔고 | 손익 |
|---|---|---|
| +5% | 1,232,258원 | +32,258원 |
| +10% | 1,264,054원 | +64,054원 |
| +20% | 1,326,381원 | +126,381원 |
| −10% | 1,133,954원 | −66,046원 |

**연 20%를 내도 첫 해 손익은 12만원이다.** 이 규모에서 자동매매의 가치는
수익금이 아니라 **① 시스템을 검증하는 것 ② 원금이 커졌을 때 쓸 수 있게 만드는 것**
두 가지다. 그렇게 보면 소액으로 시작하는 것은 매우 합리적이다.

### 권장 설정

`configs/experiment_coin.yaml` 이 이 목표에 맞춰져 있다.

```yaml
backtest:
  initial_cash: 100000
  contribution: 100000        # 매월 10만원 입금
  contribution_freq: M
  min_order_value: 5000       # 업비트 최소 주문
  cost: upbit
  allow_fractional: true      # 소수점 매매 — 소액의 핵심
  rebalance_threshold: 0.10   # 임계치를 크게 잡아 잔거래 차단
  stop_loss_pct: 0.0          # 적립·그리드와 손절은 궁합이 나쁘다
  trading_days: 365           # 코인은 연중무휴

optimize:
  strategies: [buy_and_hold, grid, vol_target, sma_cross, momentum, bollinger, zscore]
```

`buy_and_hold` + 적립 설정 = **적립식 매수(DCA)** 이며, 이것이 벤치마크다.
**어떤 전략이든 DCA를 이기지 못하면 쓸 이유가 없다.**

## 5. 적립식은 수익률 계산이 다르다

적립을 하면 잔고가 늘어나는데, 그중 얼마가 **입금** 이고 얼마가 **수익** 인지
구분해야 한다. 엔진은 두 가지를 따로 계산한다.

| 지표 | 뜻 | 쓰임 |
|---|---|---|
| **TWR** (`total_return`, `cagr`) | 시간가중수익률. 입금 시점의 영향을 제거한 **전략 자체의 성과** | 전략 비교 |
| **MWR** (`mwr`) | 자금가중수익률(IRR). 입금 시점까지 반영한 **내 돈의 실제 수익률** | 내 성과 |
| `total_invested` | 초기자본 + 누적 입금액 | 원금 |
| `final_balance` | 실제 계좌 잔고 | 결과 |
| `net_profit` | `final_balance − total_invested` | 순손익 |

둘은 크게 다를 수 있다. 실측 예 (가격이 2년간 2배가 된 경우):

```
투입원금 240만원  ->  잔고 333만원   (순손익 +93만원, 원금대비 +38.8%)
TWR  +98.0%   <- 전략 성과. 처음부터 넣었으면 이만큼
MWR  +36.2%   <- 내 돈 기준. 늦게 넣은 돈은 상승을 덜 먹었다
```

**적립식에서 "2배 올랐는데 왜 내 돈은 38%밖에 안 늘었지?"의 답이 이것이다.**
평균 매수 시점이 뒤로 밀리기 때문이며, 정상이고 피할 수 없다.

또한 **MDD는 TWR 기준으로 계산한다.** 잔고 기준으로 재면 매월 입금이 하락을
가려서 "손실이 없었던 것처럼" 보인다. 엔진은 이 왜곡을 방지한다.

## 6. 다음 단계

```bash
# 1) 업비트 시세가 받아지는지 확인
python -m quant check-data --source upbit --symbol KRW-BTC

# 2) 비용 현실 직접 확인
python scripts/small_account_sim.py

# 3) 실데이터로 최적화 + 검증
python -m quant fetch    -c configs/experiment_coin.yaml
python -m quant optimize -c configs/experiment_coin.yaml
python -m quant validate -c configs/experiment_coin.yaml   # WFE < 0.5 면 중단
```

`optimize` 결과에서 **`buy_and_hold`(=DCA)보다 나은 전략이 없다면, 그게 답이다.**
그때는 자동매매를 붙일 것이 아니라 매월 자동이체로 사는 게 낫다.
이 프레임워크의 역할은 "이길 전략을 찾아주는 것"이 아니라
**"이기지 못한다는 사실을 돈을 잃기 전에 알려주는 것"** 이다.

실전 연동 절차는 [`docs/LIVE_TRADING.md`](LIVE_TRADING.md) 참조.
