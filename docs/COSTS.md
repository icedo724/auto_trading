## 3. 거래비용 — **실제로 나가는 유일한 돈**

인프라 비용은 몇 천 원이지만, 거래비용은 **원금에 비례**한다. 이쪽이 훨씬 중요하다.

### 왕복 1회 비용

$$\mathrm{Cost}_{\mathrm{RT}} = 1 - \frac{(1-s)(1-c-\kappa)}{(1+s)(1+c)}$$

| 대상 | 수수료(편도) | 거래세(매도) | 슬리피지 | **왕복** | 10만원 거래당 |
|---|---|---|---|---|---|
| 국내주식 | 0.015% | 0.18% | 0.05% | **0.310%** | 310원 |
| 코인 (업비트) | 0.05% | 없음 | 0.05% | **0.200%** | 200원 |
| 코인 (바이낸스) | 0.10% | 없음 | 0.03% | **0.260%** | 260원 |
| 미국주식 | 0.01% | 없음 | 0.03% | **0.080%** | 80원 |

### 월 10만원 적립 · 3개월(원금 30만원) 기준 누적 거래비용

| 거래 빈도 | 3개월 거래수 | 누적 비용 | 원금 대비 |
|---|---|---|---|
| 월 1회 | 3회 | 약 1,200원 | 0.40% |
| 주 1회 | 13회 | 약 5,200원 | 1.72% |
| 주 2회 | 26회 | 약 10,400원 | 3.48% |
| **일 1회** | 90회 | **약 36,000원** | **11.99%** |

> **거래를 자주 할수록 인프라 비용은 무의미해지고 거래비용이 지배한다.**
> 하루 한 번 거래하면 3개월 만에 원금의 12%가 수수료로 나간다. VPS 3개월치가
> 2만원인데 거래비용은 3만6천원이다.
> 자세한 분석은 [`SMALL_ACCOUNT.md`](SMALL_ACCOUNT.md).

### 페이퍼 트레이딩에서는?

가상 자금이므로 **실제로 나가지 않는다.** 다만 백테스트와 동일한 비용 모델을
적용해 차감하므로, 3개월 뒤 "이만큼이 수수료로 사라졌겠구나"를 미리 볼 수 있다.
`paper-report` 의 `수수료 부담` 항목이 그것이다.

## 6. 직접 확인해야 할 항목

아래 값들은 **바뀌며, 이 문서 작성 시점의 가정**이다.
`configs/*.yaml` 의 `backtest.cost` 에서 조정할 수 있다.

| 항목 | 이 저장소의 가정 | 확인처 |
|---|---|---|
| 업비트 거래 수수료 | 0.05% / 편도 | 업비트 수수료 안내 페이지 |
| 국내주식 위탁수수료 | 0.015% / 편도 | 거래 증권사 (비대면 우대율 상이) |
| **증권거래세** | 0.18% (매도) | 국세청·거래소 (**단계적 인하 중이라 실제로는 더 낮을 수 있음**) |
| 슬리피지 | 5bp | 실전 소액으로 **실측**해야 함 |
| GitHub Actions 무료 분수 | 2,000분/월 (Free·비공개) | GitHub Billing 문서 |
| VPS 요금 | 5,000~8,000원 | 각 사업자 |
| 전기 요율 | 214.6원/kWh (2단계) | 한전 요금표·본인 누진 구간 |
| 가상자산 과세 | 미확정으로 간주 | 기획재정부·국세청 |

### 비용 가정을 바꾸려면

```yaml
backtest:
  cost:
    commission_bps: 5.0     # 편도 수수료 (bp)
    sell_tax_bps: 0.0       # 매도 거래세 (bp)
    slippage_bps: 5.0       # 슬리피지 (bp)
```

또는 이름으로: `cost: kr | us | upbit | binance | zero`

> **거래세를 실제보다 높게 잡는 것은 안전한 방향이다.** 백테스트가 보수적이 되므로
> 실전에서 예상보다 잘 나온다. 반대로 낮게 잡으면 실전에서 실망한다.
> 슬리피지도 마찬가지로 **넉넉하게 잡는 편이 낫다.**
