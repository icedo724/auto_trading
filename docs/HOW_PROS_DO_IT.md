# 실제 퀀트 트레이딩 회사는 어떻게 하는가

개인 프로젝트와 기관 운용의 차이를 항목별로 비교한다. 목적은 두 가지다 —
**따라할 가치가 있는 것**과 **따라할 수 없거나 따라할 필요 없는 것**을 가르는 것.

> 아래는 공개된 업계 관행·연구 문헌에 근거한 일반론이다. 회사마다 크게 다르며,
> 구체적 수치(비용·인원)는 규모에 따라 자릿수가 달라진다.

---

## 0. 한눈에 — 우리와 무엇이 다른가

| 영역 | 기관 | 이 프로젝트 | 격차 |
|---|---|---|---|
| 리서치 프로세스 | 가설→검증→페이퍼→소액→증액 | **동일** | 없음 |
| 워크포워드 검증 | 표준 | **있음** | 없음 |
| **다중검정 보정** | 필수 (DSR/PBO) | **추가함** (§3) | 해소됨 |
| 알파 개수 | 수십~수백 개 결합 | 1개 | **큼** |
| 데이터 품질 | Point-in-time DB, 전담팀 | 무료 소스 | **큼** |
| 실행 품질 | 시장충격 모델, TCA | 고정 5bp | **큼** |
| 리스크 모델 | 팩터 노출 관리 (Barra 등) | 없음 | 중간 |
| 인프라 | OMS/EMS, 감사 로그 | 저널 + 상태 파일 | 작음 |

## 1. 조직 — 혼자 하는 일이 아니다

| 역할 | 하는 일 |
|---|---|
| Quant Researcher | 알파(신호) 발굴. 대부분의 시간을 **폐기되는 아이디어**에 쓴다 |
| Quant Developer | 백테스트 엔진, 데이터 파이프라인, 실행 시스템 |
| Trader / PM | 자본 배분, 전략 온·오프 결정 |
| Risk | 한도 설정, 익스포저 감시, 사후 분석 |
| Ops / Compliance | 체결·정산 확인, 규제 대응, 감사 추적 |

소형 프랍은 10~50명, 대형 퀀트 헤지펀드는 수백~수천 명이다.
**"전략 하나"가 아니라 "전략을 계속 생산하는 공장"을 운영한다.**

## 2. 데이터 — 여기에 가장 큰 돈이 든다

### 기관이 사는 것

| 종류 | 예 | 대략 비용 |
|---|---|---|
| 기본 시세·기업재무 | Bloomberg, Refinitiv, FactSet | 단말당 연 수천만원 |
| 틱·호가 이력 | 거래소 직수신, Databento 등 | 연 수천만~수억 |
| 대체데이터 | 카드결제, 위성사진, 웹트래픽, 앱 다운로드 | 데이터셋당 연 수천만~ |
| 국내 | 코스콤 시세, FnGuide/Dataguide, WISEfn | 연 수백만~수천만 |

### 그런데 진짜 차이는 가격이 아니라 **정제**다

| 문제 | 기관의 처리 | 우리의 상태 |
|---|---|---|
| **Point-in-time** | "그날 실제로 알 수 있었던 값"만 저장. 재무제표 정정(restatement) 이전 값 보존 | 해당 없음(가격만 씀) |
| **생존 편향** | 상장폐지·합병 종목 포함한 과거 구성종목 이력 보유 | **미해결** — 지금 살아있는 종목만 씀 |
| 종목코드 변경·액면분할 | 마스터 매핑 테이블로 추적 | 수정주가 소스에 의존 |
| 거래정지·이상치 | 규칙 기반 클렌징 + 수동 검수 | 최소한의 검증만 |

> **개인이 메울 수 있는 것은 생존 편향 정도다.** 과거 시점의 지수 구성종목
> 목록을 구해 유니버스를 그때그때 재구성하면 크게 개선된다.
> 나머지는 일봉 가격 전략에서는 영향이 제한적이다.

## 3. 리서치 — 우리와 구조는 같고, 엄밀성이 다르다

프로세스 자체는 이 프로젝트와 동일하다.

```
가설 → 데이터 준비 → 백테스트 → 검증 → 페이퍼 → 소액 실전 → 증액
```

차이는 **검증 단계의 통계적 엄밀성**이다.

### ① 다중검정 보정 — 우리가 빠뜨렸던 것 (이제 있음)

439개 조합을 시험하고 1등을 고르면, 그 Sharpe 는 **반드시** 부풀려져 있다.
동전 439개를 던져 앞면이 제일 많이 나온 동전을 "좋은 동전"이라 부르는 것과 같다.

이 저장소에 **Deflated Sharpe Ratio** 를 구현했다(`quant/significance.py`).

```bash
python -m quant optimize -c configs/experiment_demo.yaml
```

```
통계적 유의성 (다중검정 보정)
================================================================
  관측 Sharpe             0.696
  표본 길이               2,187 봉
  시험한 조합 수            366 개
  수익률 왜도/첨도         0.17 / 4.94

  우연 기대 최대 SR       1.058   ← 366번 시도하면 이 정도는 그냥 나온다
  PSR (기준 0)            98.0%
  DSR (보정 후)           14.2%

  판정: 유의하지 않음 — 탐색 과정의 산물일 가능성이 높다
```

**PSR 98% 가 DSR 14% 로 무너진다.** 보정 없이 보면 "거의 확실히 유의"처럼 보이던
결과가, 시도 횟수를 반영하면 우연과 구분되지 않는다.

주목할 점: 이 판정은 **워크포워드(WFE 음수)와 완전히 독립적인 방법**인데
같은 결론에 도달했다. 두 방법이 일치하면 신뢰도가 높다.

| 지표 | 뜻 |
|---|---|
| **PSR** | 표본 길이·왜도·첨도를 반영해 "참 Sharpe > 0" 일 확률 |
| **DSR** | 기준선을 "N번 시도 시 우연히 기대되는 최대 Sharpe"로 올린 PSR |

기관은 여기에 더해 **PBO**(Probability of Backtest Overfitting, 조합적 교차검증),
**White's Reality Check**, **SPA test** 등을 쓴다.

### ② 알파 하나의 Sharpe 는 원래 낮다

| 오해 | 실제 |
|---|---|
| 좋은 전략 하나면 Sharpe 2~3 | **단일 알파는 0.3~0.8이 정상** |
| 하나 찾으면 계속 쓴다 | **알파 감쇠** — 수개월~수년이면 사라진다 |

기관이 Sharpe 2~3을 내는 방식은 **서로 상관이 낮은 알파 수십~수백 개를 결합**하는
것이다. 상관 0인 알파 N개를 합치면 Sharpe 가 √N 배가 된다.

> **이것이 개인이 넘기 가장 어려운 벽이다.** 알파 하나로 기관 수준의 Sharpe 를
> 기대하는 것은 구조적으로 불가능하다. 대신 목표를 "시장을 조금 이기는 것"으로
> 낮추면 개인도 달성 가능하다.

### ③ 실패를 전제로 설계한다

리서치 아이디어의 절대다수가 폐기된다. 그래서 **폐기 결정을 빠르고 싸게** 내리는
파이프라인이 핵심 자산이다. 이 프로젝트로 치면 `validate` 가 그 역할이다.

## 4. 실행 — 개인과 가장 크게 벌어지는 지점

### 시장충격 모델링

우리는 슬리피지를 **고정 5bp** 로 가정한다. 기관은 함수로 모델링한다.

$$\text{충격} \approx \sigma \cdot \left(\frac{Q}{V}\right)^{1/2}$$

주문량 $Q$, 일간거래량 $V$, 변동성 $\sigma$ — 즉 **크게 주문할수록 비용이
제곱근으로 늘어난다**(square-root law). Almgren-Chriss 류 최적 실행 이론이
"얼마나 천천히 나눠 사야 하는가"를 푼다.

### 실행 알고리즘

| 알고리즘 | 목적 |
|---|---|
| TWAP / VWAP | 시간·거래량에 맞춰 분할 |
| POV (Percent of Volume) | 시장 거래량의 일정 비율만 |
| Implementation Shortfall | 결정 시점 가격 대비 손실 최소화 |
| Smart Order Routing | 여러 거래소·다크풀 중 최선 경로 |

### TCA (Transaction Cost Analysis)

매 거래마다 **"내 체결가가 벤치마크 대비 얼마나 나빴는가"** 를 사후 측정하고,
그 결과를 다음 백테스트의 비용 가정에 되먹인다.

> **개인은 이 격차가 오히려 유리하게 작동한다.** 자금이 작으면 시장충격이
> 사실상 0이다. 10만원 주문은 호가창을 움직이지 못한다.
> 대신 **고정 수수료 비중이 크다** — 기관은 bp 단위 수수료를 협상하지만
> 개인은 그럴 수 없다.

## 5. 리스크 관리

| 층위 | 내용 |
|---|---|
| Pre-trade | 주문 전 한도 체크 (종목·섹터·총액·주문크기) |
| 실시간 | 포지션·손익·익스포저 모니터링, 자동 축소·청산 |
| **팩터 노출** | Barra/Axioma 리스크모델로 시장·섹터·스타일 팩터 중립화 |
| 사후 | VaR, 스트레스 테스트, 손익 귀인분석(attribution) |
| 규제 | 킬 스위치는 **법적 요구사항**이기도 하다 |

**팩터 중립화**가 개인에게 없는 대표적 개념이다.
"내 전략이 돈을 번 게 아니라 그냥 시장이 올라서 번 것 아닌가"를 분리해낸다.
간단한 대용은 **벤치마크(buy & hold) 대비 초과수익을 보는 것** 이며,
이 프로젝트도 `buy_and_hold` 를 항상 리더보드에 남겨 그 역할을 하게 했다.

## 6. 인프라

| 구성요소 | 역할 |
|---|---|
| Market Data Handler | 시세 수신·정규화 |
| **OMS** (Order Management) | 주문 생애주기 관리, 체결 대조 |
| **EMS** (Execution Management) | 실행 알고리즘 구동 |
| Position Keeper | 실시간 포지션·손익 |
| Risk Engine | 한도 감시 |
| Research Platform | 백테스트·데이터 접근 |

**핵심 설계 원칙 하나는 우리와 같다** — 백테스트와 라이브가 **같은 코드**를 쓴다.
둘이 갈라지면 "백테스트에선 됐는데 실전에선 안 되는" 문제의 원인을 못 찾는다.
이 프로젝트도 `PaperPortfolio` 가 백테스트 엔진과 동일한 체결·비용 규칙을 쓴다.

기술 스택은 대체로 저지연 경로에 C++/Rust, 리서치에 Python,
시계열 DB 에 kdb+/q 또는 ClickHouse 를 쓴다. HFT 는 코로케이션·FPGA 까지 간다.

## 7. 자본 배분

전략을 찾은 다음 **얼마를 넣을지**가 별개의 문제다.

| 방법 | 요지 |
|---|---|
| Kelly 기준 | 기대수익/분산으로 최적 베팅 비율. 실무에서는 **1/2~1/4 Kelly** (추정오차 때문) |
| Risk Parity | 전략별 리스크 기여도를 균등하게 |
| Mean-Variance + 제약 | 최적화하되 집중·회전율 한도를 건다 |

**전 Kelly 를 쓰면 파산 확률이 높다.** 기대수익 추정이 조금만 틀려도
과도한 베팅이 되기 때문이며, 이는 개인에게 더 심각하다(표본이 적어 추정오차가 크다).

## 8. 개인이 실제로 따라할 것 / 버릴 것

### 따라할 가치가 큰 것

| 항목 | 이 프로젝트에서 |
|---|---|
| 워크포워드 검증 | `quant validate` |
| **다중검정 보정** | `quant optimize` 의 DSR |
| 비용을 정직하게(보수적으로) 반영 | `CostModel` |
| 벤치마크 대비로 판단 | `buy_and_hold` 상시 비교 |
| 페이퍼 → 소액 → 증액 순서 | `quant paper` → `docs/LIVE_TRADING.md` |
| 전량 로깅·재현 가능성 | `Journal`, 원자적 상태 저장 |
| 생존 편향 인지 | `docs/DATA_SOURCES.md` |

### 따라할 수 없는 것 (인정하고 넘어갈 것)

- 데이터 품질·대체데이터
- 알파 수십 개 결합
- 실행 알고리즘·저지연 인프라
- 협상된 수수료

### **따라하면 안 되는 것**

- **레버리지** — 기관은 리스크 시스템이 받쳐주지만 개인은 청산당한다
- **고빈도** — 수수료 구조상 개인에게는 수학적으로 불리하다([`SMALL_ACCOUNT.md`](SMALL_ACCOUNT.md))
- **복잡한 모델** — 데이터가 적으면 과최적화만 심해진다

### 개인의 구조적 우위 (기관에는 없는 것)

| 우위 | 설명 |
|---|---|
| **시장충격 0** | 소액은 호가창을 움직이지 않는다 |
| **아무것도 안 해도 된다** | 기관은 자금을 놀릴 수 없다. 개인은 기회가 없으면 현금으로 쉬어도 된다 |
| **평가 압박 없음** | 분기 성과로 해고되지 않으니 긴 호흡의 전략을 쓸 수 있다 |
| **소형·비인기 영역** | 기관이 자금 규모 때문에 못 들어가는 곳 |

> 마지막 두 개가 특히 중요하다. **"기회가 없을 때 안 하는 것"은 개인만 가진
> 자유이고, 대부분의 개인이 그걸 안 쓴다.**
