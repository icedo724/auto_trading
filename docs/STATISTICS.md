## 1. 최댓값을 고르지 말 것 — 가장 큰 개선

### 문제

```
관측 성과 = 실력 + 잡음
```

439개 중 **최댓값**을 고르면 "실력이 큰 것"이 아니라 **"실력 + 운이 큰 것"** 을
고르게 된다. 그리고 운은 다음 기간에 재현되지 않는다.

이것은 **최댓값 추정량이 상향 편향**이라는 통계학의 기본 사실이다.
경마에서 지난 경주 1등만 계속 사는 것과 같다.

### 해법: 평균

독립인 K개 신호를 평균하면 **잡음 분산은 1/K 로 줄고 실력은 유지**된다.

```python
from quant.ensemble import build_ensemble
ensemble = build_ensemble(report, top_k=15, diversify=True)
```

`diversify=True` 가 중요하다. 같은 전략의 이웃 파라미터만 15개 모으면
신호가 거의 동일해 평균 효과가 없다. **전략 종류별로 먼저 채운다.**

### 실측 결과

같은 워크포워드 창·같은 후보군·같은 비용에서 **선택 방식만** 바꿨다
(`scripts/selection_experiment.py`, 합성 데이터 6종목 10년).

| 선택 방식 | OOS CAGR | Sharpe | MDD | WFE |
|---|---|---|---|---|
| **1등만 (argmax)** | 1.54% | **0.21** | −27.88% | 0.11 |
| 상위 5개 평균 | 3.28% | 0.52 | −13.82% | 0.23 |
| **상위 15개 평균** | 4.60% | **0.62** | −14.96% | **0.32** |
| 1등 + 변동성타겟 | 0.13% | 0.05 | −14.78% | 0.01 |
| 상위15 평균 + 변동성타겟 | 1.85% | 0.48 | **−8.88%** | 0.13 |

**Sharpe 0.21 → 0.62, MDD 절반, WFE 3배.**

### 그런데 이것이 "유의"한가 — 정직하게

쌍대 블록 부트스트랩으로 검정한 결과:

```
  상위 15개 평균
    Sharpe 0.618 vs 0.210  (차이 +0.408, 90% CI [-0.028, +0.913])
    더 나을 확률 94.3%   (유의하지 않음)
```

**90% 양측 신뢰구간이 0을 아슬아슬하게 포함한다.** 즉 "거의 확실히 낫다"고
말할 수는 없다. 다만 P(더 나음) = 94.3% 이고, **이론적 근거가 명확하며**
(최댓값 편향), MDD·WFE 등 다른 지표도 일관되게 개선되었다.

> 이런 경우의 올바른 태도: **"통계적으로 입증되지는 않았지만, 이론이 예측하는
> 방향으로 일관되게 나왔고 downside 가 없으므로 채택한다."**
> 앙상블은 비용도 늘지 않고 복잡도도 거의 없다. 틀려도 잃을 것이 없다.

## 2. 다중검정 보정 — DSR

439번 시도했다는 사실 자체가 성과를 부풀린다. `optimize` 가 자동으로 낸다.

```
  우연 기대 최대 SR       1.058   ← 366번 시도하면 이 정도는 그냥 나온다
  PSR (기준 0)            98.0%
  DSR (보정 후)           14.2%
  판정: 유의하지 않음
```

**DSR 을 올리는 방법은 세 가지뿐이다.**

| 방법 | 설명 |
|---|---|
| **시험 조합 수를 줄인다** | 아무거나 다 넣지 말고 **가설이 있는 것만** 시험 |
| **표본을 늘린다** | 기간·종목 확대 (§6) |
| **진짜 더 나은 전략을 찾는다** | 어려운 길 |

> 첫 번째가 가장 실천적이다. "혹시 되나?" 하고 그리드를 넓히는 것은
> **DSR 을 낮추는 행위**다. 439개를 돌리려면 439개만큼의 근거가 있어야 한다.

## 3. PBO — 과최적화 확률

```python
from quant.significance import collect_returns_matrix, probability_of_backtest_overfitting
matrix = collect_returns_matrix(data, candidates, config)
print(probability_of_backtest_overfitting(matrix, n_splits=10).format())
```

기간을 S개 블록으로 쪼개 **가능한 모든 절반-절반 분할**에서 "IS 1등이 OOS 에서
몇 등인가"를 본다. IS 1등이 자꾸 OOS 중간 이하로 떨어지면 과최적화다.

| PBO | 판정 |
|---|---|
| ≤ 20% | 견고 |
| 20~50% | 주의 |
| > 50% | 과최적화 — IS 1등이 동전던지기보다 못하다 |

**워크포워드와 상호보완적이다.** 워크포워드는 시간 순서만 보므로 특정 구간의
운에 좌우되지만, CSCV 는 모든 분할을 본다.

검증: 순수 잡음 데이터 → PBO 46%, 진짜 실력차 데이터 → PBO 23%.

## 4. 신뢰구간 — 점추정치를 믿지 말 것

백테스트는 "Sharpe 0.70" 하나를 준다. 그런데 그게 0.70±0.10 인지 0.70±0.60 인지에
따라 결론이 정반대다.

```python
from quant.bootstrap import bootstrap_ci, sharpe_of
print(bootstrap_ci(returns, sharpe_of).format("Sharpe"))
```

```
  Sharpe         0.651   90% CI [-0.233, 1.528]   P(>0)=87.4%   0 포함
```

**1000일(4년) 데이터로도 Sharpe 0.65 와 0 을 구분하지 못한다.**
이것이 백테스트 성과를 그대로 믿으면 안 되는 이유다.

### 왜 '블록' 부트스트랩인가

금융 수익률은 독립이 아니다(변동성 군집). 한 점씩 뽑는 단순 부트스트랩은
**불확실성을 과소평가**한다. 정상 부트스트랩(Politis-Romano)은 기하분포 길이의
블록을 이어붙여 국소 상관을 보존한다.

구현은 자기상관 정도에 맞춰 블록 길이를 자동 조정한다
(실측: iid 10.1 → 자기상관 계열 24.0).

### 두 전략 비교는 반드시 '쌍대'로

각각 CI 를 구해 겹치는지 보는 것은 **틀린 방법**이다(검정력이 낮다).
같은 날짜를 함께 재표집해 **차이의 분포**를 봐야 한다. 두 전략이 같은 시장을
겪었으므로 시장 변동이 상쇄되어 검정력이 크게 올라간다.

```python
from quant.bootstrap import compare_strategies
compare_strategies(ret_a, ret_b, sharpe_of, name_a="앙상블", name_b="argmax")
```

## 5. 변동성 타겟팅 — 예측 가능한 것만 이용하기

```python
from quant.ensemble import VolatilityScaled
strat = VolatilityScaled(base_strategy, target_vol=0.15, window=20)
```

비중을 `목표변동성 / 실현변동성` 으로 조절한다.

**통계적 근거**: 수익률의 **방향**은 거의 예측 불가능하지만, 변동성의 **크기**는
자기상관이 매우 높아 상당히 예측 가능하다. 예측 가능한 것만 이용하므로
과최적화 위험이 낮다.

### 실측 — 정직하게

| | Sharpe | MDD |
|---|---|---|
| 1등만 | 0.21 | −27.88% |
| 1등 + 변동성타겟 | 0.05 | −14.78% |
| 상위15 평균 | 0.62 | −14.96% |
| 상위15 + 변동성타겟 | 0.48 | **−8.88%** |

**MDD 는 일관되게 절반으로 줄었지만, 이 실험에서 Sharpe 는 오히려 낮아졌다.**

과장하지 않고 말하면: 변동성 타겟팅은 **리스크 축소 수단**이지 수익 개선 수단이
아니다. 합성 데이터에서는 변동성-수익 비대칭이 약해 이득이 작았고, 실제 주가지수
에서는 문헌상 더 효과가 크다고 알려져 있다. **본인 데이터로 직접 확인할 것.**

MDD 를 줄이고 싶다면 쓰고, Sharpe 를 올리려면 다른 곳을 봐야 한다.

## 6. 가장 값싼 개선 — 표본 늘리기

지금까지의 모든 통계량은 **표본이 늘면 자동으로 좋아진다.**

| 조치 | 효과 |
|---|---|
| 종목 5개 → 20개 | 유효 표본 4배. CI 가 절반으로 |
| 기간 5년 → 10년 | 표본 2배 |
| 코인 (365일) | 주식(252일) 대비 연 45% 더 많은 봉 |

```yaml
data:
  symbols: [...20종목...]
  start: "-10y"
```

**이것이 모든 통계적 기법보다 우선한다.** 표본이 부족하면 어떤 보정을 해도
"모르겠다"는 답만 나온다.

주의: 종목을 늘릴 때 **상관 낮은 종목**을 넣어야 유효 표본이 실제로 는다.
같은 섹터 20종목은 사실상 1~2개 표본이다.

## 7. 아직 구현하지 않은 것 (다음 단계)

### 생존편향 제거 — 효과 중간, 난이도 중간

지금 유니버스는 **현재 살아있는 종목**뿐이다. 과거 시점의 지수 구성종목 목록을
확보해 그때그때 재구성하면 성과 과대평가가 크게 줄어든다.
코인은 특히 심각하다 — 사라진 코인이 매우 많다.

### Purged K-Fold + Embargo — 효과 중간

지표가 여러 봉에 걸쳐 겹치므로(예: 200일 이평), 학습·검증 경계에서 정보가
새어 나간다. 경계 부근을 **잘라내고(purge)** 일정 기간을 **금지(embargo)** 하면
누수가 사라진다. (López de Prado, *Advances in Financial ML*)

### 그 밖에

- **메타 라벨링** — 1차 신호를 받을지 말지 2차 모델이 결정. 승률↑
- **HMM 국면 감지** — 국면별로 다른 전략 적용
- **팩터 중립화** — "시장이 올라서 번 것"을 분리

> **위 세 개는 표본이 충분해진 뒤에 하라.** 지금 표본으로 복잡한 모델을 얹으면
> 과최적화만 심해진다. 자유도가 늘어나는 모든 기법은 DSR 을 낮춘다.

## 8. 실행 순서 (권장)

```
1주차  표본 확대                  종목 20개 · 10년 · 상관 낮게
       ↓
2주차  현 상태 진단               optimize → DSR 확인
                                 PBO 계산
                                 bootstrap_ci 로 Sharpe CI 확인
       ↓
3주차  선택 방식 교체             argmax → 상위 15개 앙상블
       scripts/selection_experiment.py 를 본인 데이터로 실행
       ↓
4주차  그리드 축소                근거 없는 파라미터 제거 → DSR 상승
       ↓
5주차  재검증                     DSR · PBO · WFE 가 모두 개선됐는지
       ↓
       3개월 페이퍼 트레이딩       docs/PAPER_TRADING.md
```

**각 단계에서 지표가 나빠지면 되돌릴 것.** 통계적 기법은 성과를 만들어내지
않는다. **성과가 진짜인지 알려줄 뿐이다.**
